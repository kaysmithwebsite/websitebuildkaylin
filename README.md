# kaylinsmith.com

A complete real estate platform for **Kaylin Smith, Realtor & Real Estate Consultant**
(RE/MAX Epic Realty, Brokerage, Markham ON).

Static site generated by `build.py` from JSON content files and served as plain
HTML/CSS/JS. No Node.js, no build toolchain, no runtime dependencies.

---

## Quick start

```bash
python3 build.py && python3 -m http.server 8765 --directory dist
```

Then open <http://localhost:8765>.

| Command | What it does |
|---|---|
| `python3 build.py` | Development build. Unverified content renders as visible placeholders. |
| `python3 build.py --production` | Production build. Unverified content is **excluded entirely**. |
| `python3 audit.py` | Audits `dist/` for SEO, accessibility, dead controls, duplicate ids and house copy style. |
| `python3 antiai_audit.py` | Anti-AI design audit: radius, gradients, card density, centred stacks, icon spam, generated copy. |
| `python3 tools_gen_properties.py` | Regenerates demo listings. |
| `python3 tools_gen_images.py` | Regenerates placeholder imagery. |
| `python3 tools_process_photos.py [--apply]` | Turns real photographs in `incoming-photos/` into responsive assets. |

`build.py` runs a link checker on every build and exits non-zero if any internal
link is dead.

## The two-build rule

This is the most important thing to understand about the project.

Nothing about Kaylin's sales volume, client count, years of experience, awards,
rankings or testimonials has been verified, so **the build refuses to invent
them**. Content is gated on an explicit verification flag:

| Content | Gate | Dev build | Production build |
|---|---|---|---|
| Statistics | `verified: true` + a value | Dashed "Awaiting value" chips | Section omitted |
| Testimonials | `published` + `consent_on_file` | Editorial empty state | Section omitted |
| Awards / media | `verified: true` | Placeholder note | Section omitted |
| Articles | `status: published` + `byline_approved` | Rendered with a DRAFT badge | Excluded |
| Market data | non-null metrics | "Awaiting board data" | Page marked `noindex` |
| Listings | `demo: true` | Visible DEMO badge | Visible DEMO badge |

Demo badges persist into production **on purpose**: the listings genuinely are
demo records, and hiding that would misrepresent them.

Cross-links adapt automatically. When an article is excluded from production,
pages that linked to it fall back to `/insights/` rather than leaving a dead CTA.

All business content lives here. Nothing is hard-coded in templates.

### Where "unknown" is recorded, not guessed

Fields marked `_placeholder`, `_verified: false`, or left `null` are deliberate.
The site behaves correctly when they are empty:

- **No phone or email set** → no `tel:` or `mailto:` links render anywhere. The
  floating contact button becomes form-first rather than showing a fake number.
- **No Supabase configured** → forms validate fully, capture consent and lead
  source, then tell the user plainly that the message was **not** delivered.
  They never claim a success that did not happen.
- **No guide PDF** → the page offers to email the guide on release instead of
  presenting a download button that does nothing.
- **No Instagram handle** → no fake feed grid; only verified channels link out.

## Going live

1. **Contact details.** Fill in `contact.phone`, `phone_display`, `sms`, `email`
   in `data/site.json`, plus `registration.registration_number` (RECO).
2. **Database.** Run `supabase/schema.sql` in the Supabase SQL editor, then paste
   the project URL and **anon** key into `site.json` → `supabase`.
   Never put a `service_role` key there; that file is public.
3. **Photography.** Save originals into `incoming-photos/`, assign slots in
   `incoming-photos/mapping.json`, then run `tools_process_photos.py --apply`.
   See `incoming-photos/README.md` for the slot list. Any slot without a real
   photograph keeps its generated placeholder and says so in its alt text.
4. **Real content.** Kaylin's bio, neighbourhood commentary, verified statistics,
   permissioned testimonials, article byline approval, market report figures.
5. **Analytics.** Add a GA4 measurement id to `site.json`.
6. **Listings.** Replace `data/properties.json` from a licensed TRREB/CREA DDF or
   IDX feed. The normalized schema already matches.
7. Run `python3 build.py --production && python3 audit.py`, then deploy `dist/`.

`dist/` is a plain static directory. Any static host works.

## Two practices

Kaylin works as a **real estate agent** through RE/MAX Epic Realty, Brokerage, and as a
**consultant** on business, transactions, charity affairs and events. `/start/` is a
landing page that lets a visitor choose between the two; `/consulting/` covers all
four consulting domains.

`/start/` is **not** currently the site root. To promote it, swap the paths in
`build_landing()` and `build_home()` in `build.py`. Everything else follows.

## Brokerage compliance

`brokerage_identity()` in `build.py` is the single component that renders the RE/MAX
relationship, in four modes: `nav`, `compact`, `card` and `full`. It appears in the
header, on About, on Contact, on every property page and in the footer. Because it is
one function, the disclosure cannot drift between pages or be quietly dropped, and
`audit.py` fails the build if the brokerage name is missing from any page.

The official RE/MAX wordmark supplied by the client sits in the footer lockup,
used unmodified. Because the mark's blue measures roughly 2:1 against the navy
footer and brand standards forbid recolouring, it is placed on a white plate with
clear space rather than altered. `build.py` picks up any file dropped at
`assets/img/brokerage/remax-logo.{svg,png,webp}` automatically.

**The RE/MAX logo is never drawn by this build.** The balloon and wordmark are
registered trademarks that must come from official brand assets supplied through the
brokerage. While `brokerage.logo_path` is empty, the brokerage is identified in text,
which is what the regulatory disclosure actually requires, and the build warns. Do not
substitute a redrawn or recoloured mark.

Unverified by design, and flagged on every build: the full registered legal name of the
brokerage, the office address, the office phone and email, and the RECO registration
number. These were not invented.

## Resources and calculators

`data/tax-rates.json` holds every rate, bracket and rebate maximum. Nothing fiscal is
written into a component, so a legislative change is a data edit. Each rate set carries
`last_verified`; while it is null the calculators render an unverified banner and the
build warns.

`data/government-programs.json` uses the same gate. Every program carries
`last_verified`, `official_source` and `source_url`, and an ended program keeps its
entry with a "Program ended" marker rather than being deleted.

Property pages hand the price and location straight to the calculators
(`?purchase_price=…&location=…`), so a buyer never retypes what the page already knows.

### Design system

White and navy, editorial. Instrument Serif for display, Inter for interface and
data. No gradients (image legibility scrims excepted), no glassmorphism, no gold,
2px corners. Everything is tokenised in `:root`.

### Notable implementation details

- **`overflow-x: clip`, never `hidden`, on `body`.** `hidden` makes body its own
  scroll container, which pins `window.scrollY` at 0 and silently breaks the
  sticky nav, all scroll reveals and the animated counters.
- **Entrance animations are scoped to `.js`**, set synchronously in `<head>`.
  Without JavaScript nothing is hidden, so the site never renders blank. A
  load-time failsafe reveals anything an observer missed.
- **`img { height: auto }`** in the reset. Every image carries width/height
  attributes to reserve layout space; without this, constraining width leaves the
  attribute height in place and distorts the image.
- **Field ids are namespaced** (`idp=`). The filter form renders twice (inline and
  in the mobile drawer) and property pages render two forms; without namespacing
  they emit duplicate ids and break label associations.
- **Photographs are processed, not just copied.** `tools_process_photos.py` emits
  several widths per slot for `srcset`, and strips EXIF/XMP/IPTC because camera
  files carry GPS. It verifies each output is decodable and location-free, and
  refuses the file rather than publishing a corrupt or GPS-bearing image. macOS
  `sips` does *not* strip EXIF on its own, so this pass is doing real work.
- **Filter state lives in the URL**, so any search is shareable and bookmarkable.
  Cards are server-rendered for crawlers and filtered in place, not re-rendered.

## Compliance

- **TRESA.** The brokerage's legal name appears in the footer of every page.
  `audit.py` enforces this.
- **CASL.** Marketing consent is a separate, never-pre-checked control, stored in
  its own table with the exact wording shown at the time. A transactional enquiry
  never subscribes anyone to anything.
- **PIPEDA.** Lead tables allow anonymous `INSERT` only. There is deliberately no
  anonymous `SELECT` policy on any lead table; reading leads requires the service
  role.
- **CREA trademarks.** MLS®/REALTOR® attribution in the footer, with an explicit
  statement that the site is not endorsed by or affiliated with CREA.
- **WCAG 2.2 AA.** Keyboard operable, visible focus, semantic landmarks, labelled
  controls, announced validation, `prefers-reduced-motion` honoured throughout.

Legal pages are working drafts and should be reviewed by a lawyer before launch.

## Automatic email on every lead

Every lead table has an after-insert trigger that calls the `notify-lead` edge function,
which formats the record and emails it to Kaylin. The trigger calls asynchronously via
`pg_net`, so a failure to send can never roll back the insert: a lead saved without an
email is recoverable, a lead lost is not.

**This does not send anything until three things are done**, and none of them could be
done or tested here:

```bash
supabase functions deploy notify-lead
supabase secrets set RESEND_API_KEY=re_xxx \
  NOTIFY_TO=info@kaylinsmith.com \
  NOTIFY_FROM="Kaylin Smith Website <website@yourdomain.com>"
```

then either configure a Database Webhook on insert for each lead table in the Supabase
dashboard, or set `app.settings.project_url` and `app.settings.service_key` so the
trigger can call the function itself. The sending domain must be verified with the email
provider first. Until then the function returns `{sent:false, reason:"email not
configured"}` rather than pretending.

## Contrast and overlays

Text over photography is measured, not eyeballed. The method composites the
image and its scrim onto a canvas and samples the pixels behind each text run,
which is the only honest way to check contrast over a photograph.

Two token corrections came out of that work. `--ink-faint` moved from `#7C8896`
to `#626B76` (3.61:1 to 5.41:1 on white) and `--on-navy-faint` from `#6B7A8D` to
`#728296`, both chosen to clear 4.5:1 on every ground they appear on. Dark
grounds now inherit their text tokens from one canonical selector list, which is
what stops a light-theme colour leaking onto navy the way it had in the footer
and the page heroes.

Current state: **0 contrast failures across 2,955 text elements on 18 pages**,
and every element in the photographic heroes clears its requirement with margin
(worst case 5.04:1 against a 3:1 requirement). `audit.py` includes a static guard
that fails the build if text is faded below 0.8 opacity.

The hero keeps a gradient scrim, which is the single deliberate deviation from
the no-gradients rule. Without it the headline measures 3.0:1 over the newsprint
wall. It is a legibility device, not decoration, and `antiai_audit.py` reports it
separately as an accessibility exception rather than passing it silently.
